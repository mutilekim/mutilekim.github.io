The Problem

Why draws are so hard to predict

In football analytics, draws are the minority outcome — occurring in roughly 26% of matches across European leagues. Standard machine learning models optimise for overall accuracy, which means they learn to predict the majority outcomes (home wins and away wins) while almost completely ignoring draws.

A naive model that simply predicts "Home Win" every time achieves 46% accuracy on EPL data but catches zero draws. Draw Hunter 3000 was built specifically to solve this — treating draw detection as a specialised classification task rather than a general prediction problem.

The core challenge

Out of 1,752 matches across five leagues, only 463 ended in draws (26.4%). Any model that does not specifically account for this class imbalance will learn to ignore draws entirely and still report high accuracy. The solution is to use class balancing, optimise for recall rather than accuracy, and tune the decision threshold specifically for draw detection.

Methodology

How it was built

1

Data Collection

Loaded historical match data from football-data.co.uk for EPL, La Liga, Bundesliga, Serie A, and Ligue 1 (2023/24 season) using pandas read_csv with direct URLs. Combined into a single dataframe of 1,752 matches.

2

Exploratory Analysis

Analysed draw distribution across leagues (26.4% overall). Identified that draws were the minority class and that standard accuracy metrics would be misleading — confirmed the need for recall-focused evaluation.

3

Feature Engineering

Created new predictive features including half-time goal difference, home and away shot accuracy ratios, and implied draw probability from betting odds (1 / B365D). Selected 21 features covering shots, corners, fouls, cards, and odds.

4

Modelling

Trained and compared three models: Logistic Regression, Random Forest, and Gradient Boosting. Applied class_weight='balanced' to account for the draw minority class. Used stratified train/test split (80/20) to maintain draw proportions.

5

Threshold Optimisation

Generated precision-recall curves across thresholds from 0.30 to 0.60. Selected threshold 0.45 as the optimal balance — catching 77% of draws at 37% precision, nearly 1.5x the random baseline.

6

Model Persistence

Saved the trained model, scaler, and feature list using joblib and JSON for reuse on new match data without retraining.

Model Selection

Why Random Forest won

Three algorithms were trained and evaluated specifically on their ability to detect draws — not just overall accuracy.

Model Draw Recall Draw Precision Overall Accuracy Selected?

Random Forest SELECTED 66% 39% 64% ✅ Yes
Gradient Boosting 10% 29% 70% No

Why Gradient Boosting was rejected

Gradient Boosting achieved 70% overall accuracy — the highest of the three. But it only caught 10% of actual draws. This is the exact failure mode this project was designed to avoid. A model that misses 9 out of 10 draws is useless for draw prediction regardless of its accuracy score.
