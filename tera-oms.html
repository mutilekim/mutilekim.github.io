TERA School Operations Management System

A fully linked, 12-file Google Sheets system with a four-layer architecture — automating attendance tracking, fee collection, academic performance monitoring, staff management, and inventory control for The Edward Royal Academy in Vihiga County, Kenya.

Overview

The Challenge

The Edward Royal Academy is a growing CBC-aligned primary school serving students from PP1 through Grade 7. Like many Kenyan schools operating at this scale, the school was managing its operations through a combination of physical registers, manual records, and disconnected spreadsheets. There was no unified view of attendance, fees, or performance.

The principal needed a system that could give a real-time picture of the school at a glance — without expensive software, without IT support, and without requiring teachers to learn complex new tools.

No unified dashboard

Attendance, fees, staff, and inventory lived in separate, unconnected places with no single summary view.

Manual fee tracking

Fee collection was tracked manually, making it difficult to identify unpaid students or calculate collection rates quickly.

Academic data scattered

CAT and exam scores were recorded individually per teacher with no aggregated class or school-level performance view.

No inventory alerts

Stock levels for stationery, equipment, and supplies were not tracked systematically, leading to shortages discovered too late.

System Design

Four-Layer Architecture

The system was designed as a four-layer hierarchy where data flows upward automatically using IMPORTRANGE formulas. Teachers and staff only ever update their own designated sheet. The principal sees everything aggregated in real time on the Master Dashboard without touching any underlying data.

L1
Input Layer

9 Class Sheets (PP1 through Grade 7)

Each class teacher updates daily attendance (P/A/L/E), student register, and academic scores (CAT1 + CAT2 + Exam) for their class only. Auto-calculates totals and grades.

L2
Module Layer

Finance Sheet + Operations Sheet

The Finance Sheet manages fee structure configuration, M-Pesa payment tracking, and arrears flagging. The Operations Sheet manages the staff register, weekly CBC timetable, inventory tracking, and leave records.

L3
Feed Layer

Summary Tabs (Feed to Master)

Each module sheet contains a dedicated summary tab that consolidates key KPIs into a clean, structured range ready for IMPORTRANGE pickup by the Master Dashboard.

L4
Dashboard

Principal's Master Operations Dashboard

A single live dashboard pulling from all 11 underlying files. Displays attendance by class, fee collection rates, staff status, inventory alerts, academic snapshots, and prioritised action alerts — updated automatically every time any source sheet changes.

Reflection

Key Lessons

  • The right tool is the one the user will actually use. Choosing Google Sheets over a custom app meant zero adoption friction and immediate use from day one.
  • Data architecture matters even in spreadsheets. Separating input layers from summary layers from the dashboard layer made the system maintainable and scalable.
  • Automation should reduce work, not add it. Every calculation that happens automatically is one fewer thing a busy teacher has to think about.
  • Designing for the end user means designing for the principal's questions, not the developer's preferences. The dashboard surfaces answers to the questions a school leader asks every morning.
  • A setup guide is part of the deliverable. The "How To Link" sheet inside the Master Dashboard ensures the system can be maintained and extended long after handover.
